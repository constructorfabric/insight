Airbyte component and relationship map

A platform-level view of a typical self-managed Kubernetes deployment. It shows control flow, workload creation, connector protocol traffic, durable state, and the external source and destination systems. Exact service names and packaging can vary by Airbyte version and edition.

Control plane Workload and connector runtime Persistent platform dependency External system

Protocol invariant: a destination returns a STATE message only after it has successfully written every preceding record. Only then may the platform persist that checkpoint. A failure before persistence can cause records after the previous checkpoint to be sent again.

Boundary reminders

Connectors are programs

A connector image is reusable. A configured source or destination adds credentials and settings; a connection joins the two instances.

Workloads are temporary

Sync, check, discover, and spec pods are execution units. Configuration, state, logs, secrets, and destination data require durable systems outside a pod.

State is not destination data

State is a source-defined checkpoint. Losing it changes where replication resumes; it does not remove data already written to the destination.

A workspace is logical isolation

A workspace groups resources and can scope RBAC on supported editions. It is not automatically a separate database, cluster, secret store, or compute quota.
